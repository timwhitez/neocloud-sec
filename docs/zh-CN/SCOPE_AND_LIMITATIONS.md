# 范围与局限

**核心版本：** 1.0.0-draft.1 · **复核日期：** 2026-09-05

## 项目边界

本项目是面向 AI／GPU 云、自行编写且厂商中立的参考基线与实施指南，包含文档、控制目录、模板和本地检查；不是已部署安全产品、正式标准、认证、法律结论或服务商评级。NeoCloud 是工作性分类，真实信任边界仍须按服务与合同记录。

核心目录与适用的版本绑定勘误定义项目要求。外部法律、监管、合同及合格的适用性判断决定实际义务；项目映射不能证明法律合规或认证。

## 决策与保证

等级、控制数量、路线图日期、目标和复核频率是项目设计选择，不是经过证明的行业平均值。适用 T0 失败、未知、过期、无法判定或未测试时仍为 NO_GO_NONCONFORMANT。获授权的业务连续性决定可以记录在不符合基线情况下继续运营，但不能产生 PASS 或 VERIFIED。

仓库校验只检查结构和声明关系，不证明部署有效性。证据需要范围、时效、保护、适当可复现性和独立评价。人员姓名不同不自动证明独立；管理与观察路径隔离可能足够，是否物理分离取决于威胁模型。

## 技术边界

GPU 独占、硬件分区、受仲裁 vGPU 和 Device Plugin 时间切片属性不同。必须绑定硬件、固件、驱动、Hypervisor、调度、拓扑、模式、错误和生命周期状态测试。给新租户独占设备不证明旧数据已清理；介质清除指引不自动证明易失加速器状态擦除。

P_Key、NVLink 标签、Kubernetes Namespace、vCluster 或 Slurm MCS 均不是通用租户隔离证明。服务商专用控制器、数据库和带外路径需要受治理的私有访问；获批的面向客户 API 边缘不同于暴露服务商内部管理面。网络、存储、节点、GPU、遥测和支持路径应分别留证。

Attestation 只在特定信任根、策略和时效模型下报告度量声明，不证明应用行为安全、端到端密钥释放正确或无侧信道。签名仍依赖来源、密钥保管、兼容性、策略和吊销上下文。Agent 不能自行扩大当前目标／权限，但独立授权的新授权包可以批准合法的下一阶段。

## 共享责任

服务商独占信任根仍由服务商负责。客户控制的代码、Guest 配置、数据分类、租户角色和应用策略在合同边界内属于客户职责。高保证 SKU 可以不同，但必须准确描述共享资源、排除项和证据。商业标签不能代替技术控制。

## 来源与测试局限

本次补充测试使用模拟证据记录和离线检查工具；已合并的映射测试被保留，但没有在本次补充中重跑。没有主动测试生产服务、显存、Fabric、租户任务或恢复系统。[验证手册](VALIDATION_RUNBOOKS.md)描述仍需取得授权、执行并留证的工作。
